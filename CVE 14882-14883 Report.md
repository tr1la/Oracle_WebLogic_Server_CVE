## 1. Tổng hợp class map cho CVE-2020-14882/14883

### 1.1. Phase 1 — Auth Bypass (CVE-2020-14882)

Request: `GET /console/css/%252e%252e%252fconsole.portal` (double-URL-encode `../`)

|#|Class|Method|JAR|Vai trò|
|---|---|---|---|---|
|1|`weblogic.servlet.internal.ServletRequestImpl`|`getRequestURI()`|`com.oracle.weblogic.servlet.jar`|Parse URL, first decode|
|2|`weblogic.servlet.security.internal.WebAppSecurity`|`checkAccess()`|`com.oracle.weblogic.servlet.jar`|Auth filter — kiểm tra path, bị bypass vì so sánh trên path chưa normalize|
|3|`weblogic.servlet.security.internal.WebAppSecurityWLS`|`getConstraint()`|`com.oracle.weblogic.servlet.jar`|Map URL pattern → security constraint, miss `../` traversal|
|4|`weblogic.servlet.internal.WebAppServletContext`|`execute()`|`com.oracle.weblogic.servlet.jar`|Dispatch tới servlet sau khi auth pass|
|5|`com.bea.netuix.servlets.manager.SingleFileServlet`|`service()`|`consoleapp/.../netuix_servlet.jar`|Console portal servlet, decode URL lần 2 → path traversal thành công|

### 1.6. Breakpoint strategy

Set breakpoint theo thứ tự chain:

1. `WebAppSecurity.checkAccess()` — xem auth bypass happen
2. `SingleFileServlet.service()` — xem request sau bypass
3. `HandleFactory.getHandle()` — xem handle string parsing
4. `FileSystemXmlApplicationContext.<init>()` hoặc `ShellSession.<init>()` — xem gadget trigger
